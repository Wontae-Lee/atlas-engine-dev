# Atlas Engine repository instructions for coding agents

## Invariants

- Respond in Korean unless the user requests another language.
- `include/atlas/` and `src/atlas/` are the computational Core. Python and Interactive are sibling consumers; Core must not depend on either, JSON, or rendering.
- Preserve native TBB builds without a CUDA toolkit and nvcc CUDA builds. CMake selects one backend. Keep TBB and CUDA Docker runtime targets separate.
- Preserve the Python PascalCase API and select the engine before importing native classes.
- Core builders own Atlas semantic and numerical validation. Interactive `JsonCodec` checks wire structure; `CoreFactory` translates configuration to builder calls and does not duplicate validation.
- `Server` owns sessions; `Session` owns a Core `System` and no OpenGL objects. `InteractiveApplication` coordinates `Server` and optional `RenderManager`. `Renderer` never advances simulation. Headless Interactive remains graphics independent.

## Editing

- Read the relevant human documentation and source before changing behavior. Keep the corresponding documentation synchronized with intentional changes.
- New or changed code under `include/atlas/` and `src/atlas/` carries English Doxygen. Use `/** */` for multiline documentation. Elsewhere, do not add comments unless requested.
- `include/atlas/atlas.h` is generated by `tools/generate_headers.py`; do not edit it by hand.
- Every `include/atlas/` module has a matching `docs/atlas/<module>/` document. Keep module ownership and API details in that document. Update architecture documents when ownership or pipeline phase ordering changes.
- Prefer existing `DeviceBuffer`, `HostBuffer`, `parallel_for`, and host/device annotations. Preserve the shared TBB/CUDA source path and keep backend specific code behind its configured boundary.
- Keep changes scoped to the task and preserve public API names unless a change is requested.

## Task routing

| Change | Inspect |
|---|---|
| Core module | Module headers and sources; `docs/atlas/<module>/`; `docs/architecture/overview.md` |
| `System::update()` | `docs/architecture/simulation-pipeline.md` and System module |
| Core/Python/Interactive boundary | `docs/architecture/frontends.md` |
| Python binding | `bindings/python/`, `docs/frontends/python.md` |
| Interactive protocol or session | `src/interactive/`, `docs/frontends/interactive.md` |
| Rendering or state bridge | Interactive application and rendering code, Interactive guide |
| CMake/toolchain/dependencies | `docs/contributing/build.md`, `docs/contributing/dependencies.md` |
| Tests | `docs/contributing/testing.md` |
| Docker, CI, releases | Matching document under `docs/operations/` |
| Examples | `examples/README.md` and relevant example files |

The human documentation index is [`docs/README.md`](../docs/README.md). The root [`README.md`](../README.md) is the public entry point.

## Execution restrictions

- Do not run builds, tests, benchmarks, simulations, generators, or formatters unless the user explicitly asks.
- Do not claim a configured CI check passed locally. Report only commands actually completed.
